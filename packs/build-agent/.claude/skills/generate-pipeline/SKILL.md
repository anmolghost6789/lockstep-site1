# Generate Pipeline

## Prerequisites
- `/plan-build` completed (`plans/lineage.json` must exist)
- `scope_selection.pipeline = true` in session.json (skip if false — print "Pipeline was not selected in your scope. Skipping.")
- Recommended: `/generate-dml` completed so lineage is reconciled (not a hard requirement — will warn and continue with planned lineage if DML was skipped)

## Required reads (supervisor — small files only)
- `session.json` — scope_selection, planning_summary, generation_summary
- `plans/table_index.json` — wave count and table count (for pre-sizing and validation)
- `phase_handoff.json` from prior phase

**The supervisor MUST NOT read `lineage.json`, `effective_conventions.json`, or pipeline convention files directly.** All are passed as file paths to the artifact-writer delegation prompt.

## Delegation

**Always delegate to `artifact-writer` (pipeline mode).** Pipeline generation reads `lineage.json` (which can be 50–200 KB on large runs) and the platform conventions file — both belong in the sub-agent window.

## Goal

Generate platform-specific pipeline orchestration artifacts that faithfully reflect the dependency graph and wave ordering in `lineage.json`. No transformation logic is re-derived here — `lineage.json` is the single source of truth. The supervisor asks one question (platform), validates preconditions, delegates, and validates outputs.

---

## Step 1 — Scope check

Read `scope_selection.pipeline` from session.json. If false: print "Pipeline was not selected in your scope. Skipping." and exit.

---

## Step 2 — Platform selection (the ONE permitted question in this command)

Check if `scope_selection.pipeline_platform` is already set in session.json (run continuation case). If set: display as reminder and skip the question:
```
Pipeline platform already selected: Databricks Workflows. Continuing…
```

If not set, present:

```
Which deployment platform will this pipeline run on?

  1. Databricks   — Databricks Workflows (YAML job definition, tasks with depends_on)
  2. Snowflake    — Snowflake Tasks (SQL DAG with AFTER clauses, inline DML)
  3. Generic      — Platform-neutral YAML (map to Airflow, ADF, Prefect, or any orchestrator)

Your selection:
```

Map to `pipeline_platform`: `"databricks"` | `"snowflake"` | `"generic"`.
Lock in session.json: `scope_selection.pipeline_platform = "<value>"`.
Record as checkpoint decision.

---

## Step 3 — Validate preconditions

```bash
# Verify lineage.json exists
test -f state/run_id_<ID>/plans/lineage.json && echo "present" || echo "absent"

# Verify DDL artifacts exist (pipeline references target tables)
ls state/run_id_<ID>/generated/ddl/ | wc -l
```

**If lineage.json is absent:**
> "lineage.json not found. This file is generated by /plan-build Step 3. Re-run /plan-build to generate it, then retry /generate-pipeline."
Halt.

**If `planning_summary.lineage_reconciled = false`:**
> "Warning: DML corrections have not been reconciled into lineage.json. Pipeline will reflect planned lineage (pre-DML). For highest accuracy, run /generate-dml first. Continuing with planned lineage…"
Continue — do not block.

**If DDL artifacts are absent:**
> "Warning: DDL artifacts not found. Pipeline tasks reference target tables that may not yet exist. Consider running /generate-ddl before deploying. Continuing…"
Continue — do not block.

---

## Step 4 — Pre-size and plan pipeline structure

Read `table_index.json` to get total table count and wave count.

Estimate output size:
- Databricks: ~30–80 lines per task × table count + ~20 lines overhead per wave → typically 5–20 KB per wave file. Single Write for all wave files.
- Snowflake: ~15–40 lines per task × table count → typically 10–30 KB total. Single Write.
- Generic: ~20–50 lines per task × table count → typically 5–20 KB per wave file. Single Write.

All pipeline outputs are small enough for single Write. No part-file strategy needed.

Create output folder:
```bash
mkdir -p state/run_id_<ID>/generated/pipeline/
```

---

## Step 5 — Delegate pipeline generation to artifact-writer

Spawn `artifact-writer` (pipeline mode) as a single delegation (not wave-by-wave — pipeline generation is a holistic task requiring visibility of the full graph).

Delegation prompt includes:
- Artifact family: `pipeline`
- `pipeline_platform`: "databricks" | "snowflake" | "generic"
- File paths (not contents): `plans/lineage.json`, `references/pipeline_conventions/{platform}.md`, `plans/table_index.json`, `discovery/effective_conventions.json`
- Output path: `state/run_id_<ID>/generated/pipeline/`

The per-platform output file set (Databricks / Snowflake / Generic) and the six wave-generator
pipeline-mode rules the artifact-writer enforces are in
`references/pipeline_artifact_rules.md`. Pass that file's path plus
`references/pipeline_conventions/{platform}.md` in the delegation prompt.

---

## Step 6 — Self-validate pipeline artifacts

After artifact-writer returns:

```bash
# Count expected files
# Databricks: N_waves + 2 (master + readme)
# Snowflake: 4 files (tasks + activate + suspend + readme)
# Generic: N_waves + 2 (master + readme)

ls state/run_id_<ID>/generated/pipeline/ | wc -l
```

Verify:
- Expected file count matches actual count
- Master file exists and is non-empty: `test -f generated/pipeline/workflow_master.yml` (Databricks) or equivalent
- `pipeline_readme.md` exists and is non-empty
- Each wave file exists (Databricks/Generic) or all task files exist (Snowflake)

If any file is missing or empty: report the missing file, mark as incomplete in session.json, and surface to user at checkpoint. Do not re-delegate automatically — user must decide.

---

## Step 7 — Sync and checkpoint

Write pre-validation summary to `state/run_id_<ID>/generated/_validation/prevalidation_pipeline.json`:
```json
{
  "platform": "databricks | snowflake | generic",
  "task_count": N,
  "wave_count": N,
  "dependency_edges_wired": N,
  "ingest_tasks": N,
  "passthrough_tables": N,
  "circular_deps_flagged": N,
  "lineage_reconciled": true | false,
  "files_generated": ["workflow_master.yml", ...]
}
```

Sync all pipeline artifacts to `outputs/run_id_<ID>/generated/pipeline/`.

Update session.json:
- `generation_summary.pipeline_complete = true`
- `scope_selection.pipeline_platform = "<value>"` (already set in Step 2, confirm still correct)

Write `phase_handoff.json`.

Present to user:
- Platform selected
- Wave count, task count, dependency edges wired
- Ingest task stubs generated (with note about [ASSUMPTION] for actual ingest logic)
- Lineage reconciliation status: "Reconciled ✅" or "Planned (unreconciled) ⚠️"
- Files generated: list
- Any circular dependencies flagged

Recommend: `/generate-tests` (if tests in scope) or `/evaluate-build`.

Tell user: "Run `/compact focus on: run_id, phase status, user decisions, next steps` then run the next command."
