# Pipeline Conventions — Databricks Workflows

Read this when `scope_selection.pipeline_platform = "databricks"`.

Databricks Workflows are defined as YAML job definitions. Each job contains tasks. Tasks depend on each other via `depends_on`. The agent generates one YAML file per wave plus a master YAML that contains all tasks across all waves.

---

## Output files

| File | Contents |
|---|---|
| `generated/pipeline/workflow_wave_{N}.yml` | Tasks for wave N only — useful for incremental deployment or wave-level debugging |
| `generated/pipeline/workflow_master.yml` | All tasks across all waves — the primary deployment artifact |
| `generated/pipeline/pipeline_readme.md` | Deployment instructions, cluster requirements, variable substitution guide |

---

## Job structure

```yaml
# workflow_master.yml
# Generated by Build Agent — run_id: <run_id>
# Platform: Databricks Workflows
# Lineage source: planned | reconciled
# Generated at: <ISO timestamp>

name: "<run_id>_etl_pipeline"
format: MULTI_TASK

job_clusters:
  - job_cluster_key: "etl_cluster"
    new_cluster:
      spark_version: "14.3.x-scala2.12"
      node_type_id: "Standard_DS3_v2"
      num_workers: 2
      spark_conf:
        spark.databricks.delta.preview.enabled: "true"

tasks:
  - task_key: "<table_name>"
    job_cluster_key: "etl_cluster"
    sql_task:
      warehouse_id: "{{warehouse_id}}"
      file:
        path: "generated/wave_<N>/<table_name>_dml.sql"
    depends_on:
      - task_key: "<upstream_table>"
    timeout_seconds: 3600
    max_retries: 2
    min_retry_interval_millis: 60000
    retry_on_timeout: false
    libraries: []
```

---

## Task types

Use `sql_task` with `file.path` for all DML-driven tasks. The SQL file path is the `dml_file` value from `lineage.tables[].dml_file`.

For L0 raw_passthrough tables (ingest tasks), use `notebook_task` or `python_wheel_task` with a placeholder:
```yaml
  - task_key: "ingest_<source_id>"
    notebook_task:
      notebook_path: "/pipelines/ingest/<source_id>"
      base_parameters:
        source: "<source_id>"
        target_table: "<table_name>"
    depends_on: []
    timeout_seconds: 7200
    max_retries: 3
    min_retry_interval_millis: 120000
```
Add `[ASSUMPTION]` header in `pipeline_readme.md` for ingest tasks — actual notebook paths are project-specific.

## Dependency wiring

Map `lineage.dependency_graph.edges` to `depends_on` blocks:

```
lineage edge: { "from": "d_hcp", "to": "f_rx_weekly", "type": "lookup" }
  →  task f_rx_weekly.depends_on includes: { task_key: "d_hcp" }
```

Rules:
- Every edge in `dependency_graph.edges` must produce a `depends_on` entry in the downstream task.
- `execution_dependency` edges are treated identically to `data_flow` and `lookup` edges for `depends_on` purposes.
- `circular_dependency_flagged` edges: add `depends_on` to the task but add a YAML comment `# CIRCULAR DEPENDENCY FLAGGED — review before deploying`.
- L0 ingest tasks have no `depends_on` (they are roots of the DAG).

---

## Wave structure in master YAML

Tasks within the same wave have no `depends_on` relationship to each other — they are parallel. All tasks in wave N depend on at least one task in wave N-1 (enforced by the dependency edges).

Comment each task block with its wave:
```yaml
  # Wave 3 — Dimensions
  - task_key: "d_hcp"
    ...
  - task_key: "d_product"
    ...

  # Wave 4 — Facts
  - task_key: "f_rx_weekly"
    depends_on:
      - task_key: "d_hcp"
      - task_key: "d_product"
      - task_key: "d_date"
      - task_key: "stg_rx_transactions"
```

## Variable substitution

Use `{{variable_name}}` for all environment-specific values. Never hardcode:

| Placeholder | Purpose |
|---|---|
| `{{warehouse_id}}` | Databricks SQL warehouse ID |
| `{{catalog}}` | Unity Catalog catalog name |
| `{{schema_prefix}}` | Schema name prefix (e.g., `veltrex`) |
| `{{env}}` | Environment (dev / uat / prod) |
| `{{cluster_policy_id}}` | Cluster policy (optional) |

Document all required variables in `pipeline_readme.md`.

---

## Schedule (optional)

If `effective_conventions.json` contains a schedule expression, add to the top-level job:
```yaml
schedule:
  quartz_cron_expression: "0 0 2 * * ?"   # Daily at 2 AM UTC
  timezone_id: "UTC"
  pause_status: PAUSED   # Always start paused; operator enables manually
```

If no schedule is defined in conventions: omit the `schedule` block and note in `pipeline_readme.md`.

## Error notifications (optional)

```yaml
email_notifications:
  on_failure:
    - "{{notification_email}}"
  no_alert_for_skipped_runs: true
```

Use `{{notification_email}}` placeholder.

## pipeline_readme.md required sections

```markdown
# Pipeline Deployment Guide — <run_id>

## Prerequisites
- Databricks workspace with Workflows enabled
- SQL warehouse: replace {{warehouse_id}} with actual ID
- Unity Catalog: replace {{catalog}} with actual catalog name
- DML SQL files deployed to DBFS or repo at the paths referenced in task file.path fields

## Variable substitution
List every {{placeholder}} and what value to use in each environment.

## Wave execution order
Diagram or list of waves and which tables belong to each.

## Ingest tasks
List L0 ingest tasks with [ASSUMPTION] notices for notebook paths.

## Known assumptions
List all [ASSUMPTION] entries from lineage.json.
```

## Pipeline test output format

When generating pipeline tests for Databricks (`tests_pipeline/pipeline_tests.py`):

```python
# pipeline_tests.py — Databricks pipeline tests
# Generated by Build Agent — run_id: <run_id>
# Tests: task completeness, dependency correctness, wave isolation,
#        idempotency markers, retry/timeout presence

import pytest
import yaml
import json

WORKFLOW_MASTER = "generated/pipeline/workflow_master.yml"
LINEAGE_FILE    = "plans/lineage.json"

@pytest.fixture(scope="module")
def workflow():
    with open(WORKFLOW_MASTER) as f:
        return yaml.safe_load(f)

@pytest.fixture(scope="module")
def lineage():
    with open(LINEAGE_FILE) as f:
        return json.load(f)

def test_all_lineage_tables_have_tasks(workflow, lineage):
    """Every non-passthrough table in lineage has a corresponding task."""
    task_keys = {t["task_key"] for t in workflow["tasks"]}
    for table in lineage["tables"]:
        if not table.get("raw_passthrough"):
            assert table["table_id"] in task_keys, \
                f"Missing task for table: {table['table_id']}"

def test_dependency_edges_wired(workflow, lineage):
    """Every dependency_graph edge maps to a depends_on entry."""
    task_map = {t["task_key"]: t for t in workflow["tasks"]}
    for edge in lineage["dependency_graph"]["edges"]:
        if edge["type"] == "circular_dependency_flagged":
            continue
        downstream = edge["to"]
        upstream   = edge["from"]
        assert downstream in task_map, f"Downstream task missing: {downstream}"
        dep_keys = [d["task_key"] for d in task_map[downstream].get("depends_on", [])]
        assert upstream in dep_keys, \
            f"Edge {upstream} -> {downstream} not in depends_on"

def test_all_tasks_have_retry(workflow):
    """All tasks must have max_retries > 0."""
    for task in workflow["tasks"]:
        assert task.get("max_retries", 0) > 0, \
            f"Task {task['task_key']} has no retry policy"

def test_all_tasks_have_timeout(workflow):
    """All tasks must have timeout_seconds set."""
    for task in workflow["tasks"]:
        assert task.get("timeout_seconds", 0) > 0, \
            f"Task {task['task_key']} has no timeout"

def test_wave_isolation(workflow, lineage):
    """No task depends on a task more than one wave ahead."""
    wave_map = {}
    for wave_num, tables in lineage["dependency_graph"]["waves"].items():
        for t in tables:
            wave_map[t] = int(wave_num)
    task_map = {t["task_key"]: t for t in workflow["tasks"]}
    for task in workflow["tasks"]:
        task_wave = wave_map.get(task["task_key"], 0)
        for dep in task.get("depends_on", []):
            dep_wave = wave_map.get(dep["task_key"], 0)
            assert dep_wave < task_wave, \
                f"Task {task['task_key']} (wave {task_wave}) depends on " \
                f"{dep['task_key']} (wave {dep_wave}) — wave ordering violation"

def test_incremental_tables_have_watermark_reference(lineage):
    """All INCREMENTAL tables declare a watermark_column in lineage."""
    for table in lineage["tables"]:
        if table.get("load_strategy") == "INCREMENTAL":
            assert table.get("watermark_column"), \
                f"INCREMENTAL table {table['table_id']} has no watermark_column in lineage"
```
